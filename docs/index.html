One Deterministic Simulation, Three Places It Runs

Glory Days Web is a 2.5D side-scrolling air-combat & lane-RTS multiplayer game. Instead of duplicating physics or AI between server and browser, the shared/ folder contains pure ES modules imported directly by the Node server, the Browser client (for offline play & 60 Hz prediction), and the node:test suite.

1. Shared Core shared/ (6,895 LOC)

Single Source of Truth

constants.mjs holds every world dimension, unit stat, and tuning schema. simulation.mjs runs deterministic 60 Hz flight physics, ground combat, AI commanders, and snapshot reconciliation.

2. Authoritative Server server/ (658 LOC)

Zero-Dep HTTP + RFC 6455 WS

Built purely on node:http and node:crypto. Serves static assets (and maps /shared/*), hosts multi-room matches (ALPHA, BRAVO, CHARLIE), ticks at 60 Hz, and broadcasts snapshots at 20 Hz.

3. Browser Client public/ (3,469 LOC)

Predict, Render & Synthesize

main.mjs connects via /ws (with automatic offline sandbox fallback), runs local 60 Hz prediction between snapshots, renders 42 PNG sprites on Canvas 2D, and synthesizes SFX with Web Audio.

4. Simulation Loop & Multiplayer Netcode

Switch tabs to trace either the WebSocket sync loop or what happens inside a single 1/60s tick.

Why 60 Hz Prediction?

Waiting for 20 Hz (50ms) snapshots would feel sluggish. Running stepSimulation() locally keeps aircraft flight silky smooth at 60+ fps.

Reconciliation Contract

reconcileClientState() smoothly merges authoritative 20 Hz server snapshots into local state, preserving responsiveness without drift.

Event Deduplication

Both local prediction and server snapshots emit state.events. main.mjs deduplicates them via seenEventKeys before playing SFX.

6. Dev Labs, 6 Golden Invariants & First-Day Checklist

How tuning labs work safely without touching live matches, plus rules you must never break.

Flight Lab (/flight-lab) Protected / Do Not Edit

public/flight-lab.html + flight_lab.mjs. Uses P47_TUNING_SCHEMA & HELI_TUNING_SCHEMA, saves presets to localStorage, and syncs live tweaks via ?tuner=1 / tunerOnly WS without joining ALPHA.

Ground Lab (/ground-lab) Unit & Bunker Sandbox

public/ground-lab.html + ground_lab.mjs. Exposes GROUND_UNIT_TUNING_SCHEMA, GROUND_BEHAVIOR_TUNING_SCHEMA, and BUNKER_TUNING_SCHEMA to test columns, crossfire, and AA behavior interactively.

1. Flight Lab Isolation

Never edit flight-lab.html or flight_lab.mjs unless explicitly tasked; preserve P47_TUNING_SCHEMA, updateP47Config, updateP47, and updateCrashSlide.

2. Dual Relative Imports

Files in public/js/*.mjs MUST import shared files with relative ../../shared/... (never /shared/...) so both Node tests and HTTP server resolve them.

3. Lean Dependency Policy

Built-in Node 22 APIs (node:http, node:crypto, node:test) & pure browser APIs first; avoid adding npm packages without clear payoff.

4. Keyboard & Zero-Modal Pad

In-match flight, weapons, and requisitions are 100% keyboard-driven. Base pad landing repairs, reloads, and banks civilians passively with zero popups.

5. Snapshot Completeness

Because clients predict via stepSimulation(), createNetworkSnapshot() must include every top-level field it reads (e.g., baseAa, nextEntityId, botThinkCooldown).

6. tunerOnly Lab WebSockets

Connections from /flight-lab, /ground-lab, or ?tuner=1 are marked tunerOnly in server/index.mjs so they never take human slots in rooms.
